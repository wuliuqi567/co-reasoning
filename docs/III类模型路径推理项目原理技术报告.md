# III类模型路径推理项目原理技术报告

摘要：
本文档面向 co-reasoning 项目中的 III 类模型路径推理能力，给出系统目标、技术路线、核心算法、训练与部署机制、协同推理输出机制以及工程实现约束。该项目以图结构网络为对象，将链路时延、带宽、利用率、丢包率与节点/链路在线状态统一映射到强化学习环境中，通过 DDQN 智能体在离散动作空间内进行逐跳决策，实现故障与拥塞约束下的可达路径推理。相较于传统一次性最短路计算，本方案在“可路由子图”与“策略推理”双重约束下工作，既能输出当前策略路径，也能输出同条件下最短路径用于质量对比，并支持与 II 类本地策略的协同优化。

关键词：
III类模型；路径推理；强化学习；DDQN；网络重路由；协同推理

一、项目背景与总体目标
本项目服务于分层协同网络智能体体系中的 III 类全局推理节点，核心任务是在 II 类节点/链路失效、链路拥塞或质量恶化场景下，为给定源端设备与目的端设备生成可执行的重路由路径，并以统一指标（时延、带宽、丢包率、响应时间）参与本地-全局策略对比。工程入口位于 `rl_reroute.py`，其流程体现了 III 类模型在协同链路中的职责：接收业务源宿信息，加载全局模型进行推理，产生全局策略，再与 II 类上报策略进行比较后输出最终策略。训练与推理统一基于 `environment/net_tupu_iii.py` 中的 `NetTupu` 环境，保证“离线训练—在线推理”语义一致。

从系统目标看，III 类路径推理并不单纯追求图论意义上的最短时延，而是强调可执行性与鲁棒性：第一，决策必须满足当前时刻可路由约束；第二，策略需避免明显绕路与重复回环；第三，在可达路径存在时优先获得低时延高质量路径；第四，在协同推理阶段能够与 II 类局部策略进行可比性评估并形成统一下发结果。

二、系统原理与技术路线
项目采用“知识更新图 + 可路由子图 + 强化学习决策 + 指标对比”的技术路线。底层图数据来自 II 类拓扑图及其状态更新结果，环境侧通过图属性标准化与状态过滤机制构建当前可决策空间。对于部署模式（`test=True` 且 `execute_reroute=True`），`NetTupu` 会优先加载 `latest_II_class.base.graphml`，再通过知识更新接口刷新节点与链路状态，形成可能含故障标记的当前运行图，并据此建立工作图。对于训练模式，可使用 `latest_II_class` 或历史拓扑，并按配置概率动态加载不同时刻链路状态，提升策略泛化能力。

在路径推理层，系统并行维护两条语义链路。其一是“策略路径”：由智能体逐步选择邻居节点得到，反映策略真实行为。其二是“参考最短路径”：在同样故障与质量约束下，以 `link_latency` 为权重通过 Dijkstra/最短路计算得到，反映当前图条件下理论最优基准。二者共同输出，既可用于训练奖励构造，也可用于部署时效果评估和协同比较。

三、核心模型与环境机制
III 类模型采用 DDQN 架构（配置见 `config/ddqn.yaml` 与实际运行配置），动作空间为当前节点可用邻居的离散下标，观测空间采用 `state` 模式为主。`state` 观测向量由“全节点状态特征 + 当前节点 one-hot + 目标节点 one-hot”组成，其中每个节点特征包含在线状态、访问标记与固定槽位邻居特征。邻居槽位单元编码为 `[mask, delay_norm, utilization, link_on, loss_rate]`，在固定 `num_nodes` 与 `max_degree` 的前提下形成稳定维度输入，保证训练模型与部署模型结构兼容。

路径可行性由可路由子图定义。环境通过 `_get_routing_graph()` 对原始工作图做过滤：节点需在线，边需在线，且链路利用率不超过 `utilization_threshold`、丢包率不超过 `loss_rate_threshold`。因此，智能体所有可选动作都来自“可路由子图中的真实邻居”，天然满足故障与拥塞约束。环境中 `step()` 的决策流程包含：获取可选邻居、解析动作、计算单步时延、进行可达性检查、计算奖励、更新路径状态与终止标志。若无可选邻居则判定断连终止；若动作无效则给予惩罚并保持节点不迁移。

奖励函数由 `RewardCalculator` 实现，遵循“有效推进奖励、异常行为惩罚、到达目标按质量给奖”的原则。典型项包括无效动作惩罚、断连惩罚、步进惩罚、进展奖励、回环惩罚、超时惩罚和到达奖励。到达奖励同时考虑“整条路径质量”与“最后一跳是否明显绕路”，可抑制临近目标节点时的不合理长跳行为。设当前累计时延为 $D_{path}$、当前步时延为 $d_{step}$、同约束最短路径时延为 $D_{sp}$，则到达时总时延为 $D_{tot}=D_{path}+d_{step}$，质量比为 $q=\mathrm{clip}(D_{sp}/D_{tot})$。当策略与最优基准接近时，终止奖励上升；当存在显著绕路时，奖励降低，从而引导策略收敛到稳定且高质量路径。

四、训练、推理与协同输出机制
训练阶段，环境可按 `dynamic_topo_prob` 从 `environment/jsondata/data_topo_link_info` 随机加载不同时刻链路状态，通过属性更新而非拓扑重建实现“同拓扑、异状态”训练样本扩充。这一机制使智能体在不同拥塞/故障分布下学习更稳健的选路策略。推理阶段，`rl_reroute.py` 加载训练完成模型，执行单回合重路由，输出策略路径与对比最短路径的多维指标，包括路径节点端口映射、时延、带宽、丢包率与连通性判断。

协同层面，III 类节点会拉取 II 类本地策略，并通过 `policy_compare` 进行全局与本地策略比较。比较结果作为最终下发策略基础，实现“本地快速响应 + 全局优化纠偏”的协同效果。为便于观测与审计，系统记录完整阶段日志（检测触发、查询知识、模型推理、协同优化、策略下发与结束状态）并构造统一性能结果串，支撑后续分析与复盘。

五、工程约束与实现要点
本项目在工程上强调三类一致性。第一是维度一致性：`num_nodes` 与 `max_degree` 由拓扑结构确定并保持稳定，避免训练与部署输入维度漂移。第二是语义一致性：策略路径、参考最短路径、可路由子图过滤规则在训练与部署保持统一，防止离线效果与在线表现割裂。第三是信息一致性：`info` 中同步输出路径、最短路径、故障明细、动作掩码与连通性，确保上层协同模块可直接消费。

同时，系统以“状态标记优先”而非“删点删边”管理故障，既保留原始拓扑完整性，也支持故障前后路径对比与追踪。路径指标计算遵循统一口径：时延按边累计、带宽取瓶颈最小值、丢包率按分段成功率累积得到，便于跨策略横向对比。

六、结论
III 类模型路径推理项目以强化学习为核心，将网络拓扑状态、链路质量约束与协同策略机制融合为一体化决策系统。其关键价值在于：能够在故障与拥塞条件下生成可执行路径；能够通过最短路基准度量策略质量；能够与 II 类策略形成协同优化闭环。按当前实现，该体系已具备面向工程部署的完整链路与可观测性。后续可在不改变整体架构的前提下，进一步增强多目标奖励权重自适应、策略不确定性估计与跨时间窗策略平滑，以提升复杂网络态势下的稳定性与泛化能力。
